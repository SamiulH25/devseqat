# CLAUDE.md: Ironfield project map

Read this first; it is written so a new session can start work without exploring the code.
For a member-level index (every type and method with its line number) read `docs/CODEMAP.md`.
For how each system works in depth (data model, tick order, damage path, campaign layers, data formats, worked examples,
troubleshooting) read `docs/DEVELOPING.md`.
Keep both current: see "Keeping this map current" at the end.

## Workflow for every change (follow in order)

1. Find the code: use the "File guide" table below, then `docs/CODEMAP.md` for the exact line of a method.
2. Make the smallest change that does the job. Match the style of the code around it. Do not reformat or move code you are not changing.
3. If you added behaviour, add or extend a test (see "Recipes").
4. **UI and visuals:** Whenever working with UI or visuals, capture screenshots (`IRONFIELD_SHOTS`, `IRONFIELD_CAMPAIGN_SHOTS`, etc.) and check them yourself. No visual judge (no subagent rating the shots). Exception (2026-11-21, the user's call): the per-people street art pass is rated by Hydrogen (T3 `antigravity`, `gemini-4-hydrogen`) on `IRONFIELD_STREET_ONLY` shots.
5. Run `tools/check.sh`. It must end with `ALL CHECKS PASSED`. If it fails, fix the cause; never weaken or skip a test to get green.
6. If you added, renamed or moved a method or file: `git add` new files, run `tools/codemap.sh`, and update the tables here if a file's job changed.
7. Commit with a short message saying what changed and why.

## What this is

**Ironfield**: a 2.5D medieval battle + campaign game. C# / .NET 10 / MonoGame 3.8 DesktopGL. One project
(`Ironfield.csproj`, namespace `Ironfield`, ~17k lines). **No content pipeline**: unit sprites are painted by code (`SpriteSheet.cs`) and baked to PNGs in `Data/sprites/`, which the game loads (the PNGs are the product, the code the pipeline); terrain, font,
sound cues and beds are generated in code and scores render through a micro-sample bank; shaders are plain GLSL compiled at runtime. The only data is `Data/sprites/*.png`, `Data/*.json`, `Data/events/*.json`, `Data/music/*.json` and `Data/audio/instruments.bank`.
`Content/Content.mgcb` has settings only, no content items.

## Commands

```bash
tools/check.sh                                           # build + rule checks + self-test; run before every commit
tools/check.sh --quick                                   # same without the self-test (while iterating)
dotnet build -c Release                                  # ~30 s cold, warnings are expected (CS0649 on JSON DTOs)
dotnet run -c Release --no-build -- --selftest           # THE test suite (headless; one process per core, ~2 min on 4); CI runs exactly this
dotnet run -c Release --no-build -- --selftest Parry     # one test by SelfTest method name
dotnet run -- --balance 4                                # N headless campaigns+battles -> balance/*.csv (gitignored)
dotnet run -c Release -- --pacing 8                      # stand-in captain only: career stage days vs targets (~10 min)
dotnet run -- --replay [file]                            # replay replays/last-battle.json, check same outcome
dotnet run -- --write-controls                           # write default controls.json
dotnet run -c Release --no-build -- --sprites out.png torso.plate helm   # headless: chosen sprite parts 6x on one PNG (pixel-art check)
dotnet run -c Release --no-build -- --bake-sprites                      # paint parts the code has but Data/sprites lacks; keeps existing (maybe hand-edited) PNGs
dotnet run -c Release --no-build -- --bake-sprites --force helm.kettle  # repaint matching PNGs from code (no filter = all); --check lists PNGs that differ from the code
tools/sprite_tool.py show helm.kettle.f                                 # a part as a text grid with its legend (team colours starred); write KEY FILE, lint, team
dotnet run -c Release --no-build -- --portraits out.png [seed]   # headless: lords' and kin's painted faces 3x on one PNG (first four: one face in each mood)
dotnet run -c Release --no-build -- --sounds /tmp/snd [filter]   # headless: matching cues (all versions, near then far), beds and stereo music scores as 44.1 kHz WAV
dotnet run -c Release -- --bench 1500                    # headless 1500-a-side battle: ms per tick by stage (3000 men ~3.6 ms)
dotnet run -c Release -- --realms 8                      # snowball guard: N campaigns x 240 days, realm shares -> balance/realms.csv (~3 min)
dotnet run -c Release --no-build -- --tiers 3 [filter]          # TI0: every upgrade link against its parent at equal men, upkeep and places -> balance/tiers.csv (~3 min, all cores)
dotnet run -c Release --no-build -- --kit                       # KT4: every man's built numbers (base + skills + kit) vs balance/kit-before.csv -> balance/kit-after.csv
dotnet run -c Release -- --grounds 24                    # same army both sides on each field layout, ground chosen by each in turn -> balance/grounds.csv (~2 min)
dotnet run -c Release -- --agree 4 5                     # fought vs auto-resolved: equal-Might fights by tier gap, at DrillWeight and at 5 (~2 min)
dotnet run -c Release --no-build -- --events 4                   # events: N campaigns x 240 days with the stand-in, how often each fired and which never -> balance/events.csv (~4 min)
dotnet run -c Release -- --arcana 4                      # magic and aura census (docs/archive/ARCANA.md AR0): N seeds x 240 days, seeking and plain stand-in -> balance/arcana.csv (~6 min)
dotnet run -c Release -- --campaign-bench 30             # headless campaign for N days: ms a day by tick stage (~76 ms on the 115-province map)
dotnet run -c Release --no-build -- --tester-saves [filter] # playtest saves test-01..12 (fresh start, sandbox, big battle, siege, circle, order, monsters, port, muster...) into the save folder (`IRONFIELD_SAVES` or the real one), named on LOAD (~2 min; TesterSaves.cs)
tools/playtest.py start NAME [--seed N|--scenario ID]; tools/playtest.py send NAME <command>   # agent playtest harness (docs/PLAYTEST_HARNESS.md)
tools/playtest.py fleet N --parallel P --brief "..."        # N claude agents, one headless session each, then playtest/REPORT.md
dotnet run -c Release --no-build -- --world-bench [seed] # headless: the campaign map's terrain and world meshes, ms and verts by stage, a checksum that must not change (~0.4 s)
dotnet run -c Release --no-build -- --relief out.png [layout] [px]  # headless: a layout's land as shaded relief with roads, cliffs, places (default 6, the 4x draft; ~3 s)
```

`IRONFIELD_MAP_HOUR=11` (campaign shots: the map's hour; a new campaign starts at 01:00, night), `IRONFIELD_MAP_FIGURE=1` (debug: a party rider's size on the map, default 2.5; docs/pre-demo/WORLD_SCALE.md), `IRONFIELD_SHOTS_FROM=clash|hud|sergeants|magic|spectacle|workings|poses|roster|life|beasts|captain|hunted|arrows|named` (shots: start at the melee clashes, the two battle views (`fight-*.png`, `command-*.png`, about a minute), the sergeants' command UI (a quick battle in deployment), the magic, the spectacle, the workings scenes, the grip/shooter/stance pose sheets, the realms' new troops, the idle-and-falls sheet, the spiders, bears and wyverns, the enemy marking the captain, hunting him, the arrow scenes, or your named men in the fight), `IRONFIELD_DUMP_ATLAS=/x.png`, `IRONFIELD_ANIM=/dir` (soldier animation strips, eight frames a clip, front and side, `AnimSheet.cs`; `IRONFIELD_ANIM_ONLY=name` filters clips), `IRONFIELD_GPU_REPORT=1` (same as `--gpu-report`), `IRONFIELD_LOD=0..1` (pins the battle's detail distances: 0 = the floor, 1 = full; normally they follow the frame rate, and shots draw at 1). `IRONFIELD_TROOPS=/dir` (every troop standing as a transparent PNG, `TroopSheet.cs`; add `IRONFIELD_TROOP_VIEWS=id1,id2` for 6-angle turnarounds), `--bench-3d [n]` (3D mesh emission ms & tris across LOD tiers), `IRONFIELD_SYSTEM_CURSOR=1` (on Linux the game draws its own cursor, `ScreenHost.DrawCursor`, because SDL's system cursor can fail to show on Fedora/Wayland; this switches back to the system one). `--cursors out.png` writes a sheet of every cursor.

## Architecture in one screen

```
Program.cs  CLI switches (--selftest/--balance/--replay/--write-controls) else runs ScreenHost
ScreenHost  MonoGame Game. Mode {Title, Map, Battle, Loading}; owns Art, Audio, Settings, Controls (Ctl), Shading, Quality
            Loading: new/continued campaigns are made on a worker thread (`Load`: Campaign.New + MapScreen.Prepare) behind a loading screen (`TitleScreen.Loading.cs`)
            (Prepare also bakes the map's `World` meshes headless; `World.Upload` sends them to the GPU on the main thread: keep slow mesh work off it)
  TitleScreen ── New/Continue/QuickBattle ──┐   New opens CreatorScreen (the character creator)
  MapScreen (campaign UI + 3D map) ◄────────┤   SettingsScreen overlay on any mode
  BattleScreen (battle UI, camera, render) ◄┘

HEADLESS (no MonoGame graphics; must stay that way so --selftest runs):
  Battle (partial: Battle.cs, BattleAI, BattleCombat, BattleMove, BattleMorale, BattlePlayer, BattleSiege, BattleCaptain, BattleGrid,
          BattleDivision, BattleCreatures, Replay)
     uses Squad, Unit/UnitType/Mount/Look (Units.cs), Troops (Data/troops.json), Terrain, BattleOptions/Weather
  Campaign (partial: Campaign/Campaign.cs, CampaignBattle, CampaignActions, CampaignAI, CampaignWar, CampaignSiege, Career, Characters, ...)
     state = CampaignState (all save data, plain fields -> JSON), Rules (static company math), WorldMap, Rng, Balance, Names
```
`Vector2` is used for both, but only `Microsoft.Xna.Framework` math types are allowed in headless code (no GraphicsDevice etc.).

### Campaign -> battle -> campaign hand-off
`MapScreen` encounter panel -> `Campaign.PrepareBattle(enemy)` (or `PrepareAssault(settlement)`) builds a `BattleSetup`
(`ArmySpec`s via `Rules.Army`, `BattleOptions` from perks/gear/weather/terrain, seed) -> `MapScreen.OnBattle` event ->
`ScreenHost.StartCampaignBattle` (autosaves) -> `BattleScreen.BeginCampaign` -> `new Battle(seed, player, enemy, options)` ->
deployment phase -> fight -> `Battle.Result()` = `BattleResult` -> `ScreenHost.FinishCampaignBattle` -> `Campaign.FinishBattle`
-> `Apply` (wounds/killed, XP, loot, ransom, prisoners, officers) -> `BattleReport` -> `MapScreen.ShowResults`.
Auto-resolve skips the battle: `Campaign.AutoResolveEncounter` -> `Rules.AutoResolve` -> same `Apply`.
`ArmySpec` = list of `Company(troop id, count, role, id, ...)`; `CompanyResult.Id` maps back to `CompanyRecord.Id`.

### Battle tick (`Battle.Update(dt)`, fixed 1/60 s in tests)
ApplyDirects -> RecordFrame -> BuildGrid -> centroids -> `General(team)` every 0.5 s (enemy AI, and own side if AutoPlayer/AI squads) ->
`UpdateDivisions` (arrived goals, `AiCommand`, each division's `Brain`) -> `UpdateSight` (every 0.5 s) ->
Batter (siege gate) -> Reinforce (1 s) -> called horse, Resupply -> `UpdateReliefs` -> `UpdateSquad` each (and `UpdatePath`, `UpdateOrders`) -> per unit: `UpdatePlayer` or `Think`
(`ThinkCav` for cavalry), `TickAction` (windup/strike/recover), `Tire` -> `Move` (steering, separation, terrain, wall) ->
`Braces`, `Lances` -> `UpdateArrows` -> `UpdateMorale` -> `CheckEnd` (sets `Winner`).
Files: tick/setup/result in `Battle.cs`; `Think`/`ThinkCav`/`General` in `BattleAI.cs`; `UpdatePlayer` in `BattlePlayer.cs`;
`TickAction`/`Strike`/`Hit`/`Kill`/arrows/`Braces`/`Lances` in `BattleCombat.cs`; `Move` in `BattleMove.cs`; `UpdateMorale` in `BattleMorale.cs`.
Damage path: `Strike` -> `Hit(attacker, target, ...)` (block/parry, flank via `SideOf`, speed bonus, slope) -> `Kill`. Horses: `HitHorse`.
Men think on a stagger (`ThinkNow`: near the enemy every tick, else every 2nd/4th) and morale every 2nd tick, keyed on the tick counter.

### Divisions (docs/archive/COMBAT_OVERHAUL.md)
A `Division` (BattleDivision.cs) is a group of squads under an officer (`Unit.Sergeant`) at a `Post` (Front, LeftWing, RightWing, Skirmish,
Reserve) keeping a `Stance` (three per post); `Goal` is the pair (docs/archive/OFFICERS.md). `Brain` (BattlePosts.cs) turns them into his companies'
orders; where a post lies comes from the side's `FrontLine`, and he never changes his stance himself. Division squads are excluded from
`Commanded` and the general's `Led()`. `IssueGoal` sets `Pending`, which takes over on the next tick (orders land at once: docs/archive/OFFICERS.md OF0; the riders
that once carried them were removed 2026-11-19). `Direct(squad, act)` sends a plain order and sets `Squad.Override`. Divisions come from
`ArmySpec.Divisions` + `Company.Division` (`BuildDivisions`); the campaign fills them from `CampaignState.Divisions`
(`Campaign.WithDivisions`, Campaign/Divisions.cs); `Armies.Divide` splits big AI armies. Battle UI: `Hud.Divisions.cs`, Y key.

Battle randomness uses its own seeded `rng` only: replays (`Replay.cs`) must reproduce exactly, so never use `Random.Shared`
or wall-clock time in the sim; `SelfTest.ReplayExact` checks it. In the campaign and the sim, mix numbers with `Rng.Mix` / `Rng.Of`, never
`HashCode.Combine` or `GetHashCode` (seeded afresh in every process: a save would get other weather and battle seeds); `tools/check.sh` refuses them.

### Campaign tick (`Campaign.Tick(hours)`, 0.25 h steps, stops on `Encounter`/`Arrived`)
Ticks live in `Campaign.cs`; the AI they call (`LordThink`, `BanditThink`, `FactionAI`) in `CampaignAI.cs`.
`Hourly` (lord/bandit AI: `LordThink`, `BanditThink`, contracts, `SiegeHourly`) / `Daily` (healing, drill, food `EatDaily`,
`ArmiesDaily`, `FactionAI`, sieges, truces) / `Weekly` (upkeep, income, garrisons, prisoners, desertion) -> `Move` -> `Encounters`.
Player actions (most in `CampaignActions.cs`) are public methods on `Campaign` returning `string?` (null = success, else the reason shown in the UI):
`Hire`, `RecruitLevies`, `BuyHorses`, `BuyGear`, `Upgrade`, `Split`, `Rest`, `SignContract`, `Besiege`, `Station`, `SellPrisoners`,
`SwearFealty`, `ProposeWar`, `SetObjective`, `DeclareIndependence`, `DeclareWar`, `OfferPeace`...
`Daily` ends with `FiefsDaily` then `CareerDaily` (rulers, councils due, rank beats, win/loss). Events the map must show once are plain fields:
`Encounter`, `Arrived`, `Report`, `Beat` (and the saved `S.Event`, an event waiting for a choice). Map screens on keys: P party, K skills, I kit and baggage, C camp, J quests, L lords, R realm, V divisions, M realm map, B siege, F1 key help (`Act` entries, table `MapScreen.Screens`; `OpenScreen`/`CameFrom` remember the party screen as the way back).

## Recipes

- **Add a test:** write `static void Name()` in the matching `Tests/*Tests.cs` file using `Check(cond, "message")`, and add it to the `Tests` list in `SelfTest.cs`. Tests run in separate processes, in no fixed company, so a test must not lean on an earlier one's state.
  Scenario fields: `Battle.Empty(seed)` (flat terrain, two leaders) + `AddSquad`/`Spawn`, then loop `b.Update(1/60f)`.
- **Add/change a troop:** edit `Data/troops.json` (stats, `upgradesTo`, `look`, mount). `Troops.Validate` + `SelfTest.TroopTree`
  enforce: links exist, upgrades raise tier and are better, every troop reachable from `levies`. New look parts need painting
  code in `SpriteSheet.cs` (keys `part.variant.view/palette`), then `--bake-sprites` (`SelfTest.SpritesBaked` fails until baked).
  Then refresh the map of the trees: `python3 tools/troopmap.py --write` (docs/TROOPS.md, every troop, branch and bridge).
- **Change how a sprite part looks:** edit its PNG in `Data/sprites/parts/` (team parts, drawn in the Azure palette; other sides are a colour swap of it,
  so keep the master's team colours for team cloth) or `Data/sprites/neutral/` (horse coats, faces). Keep its size (the rig reads metres from pixels).
  Parts whose charge differs by side also have per-palette copies in `Data/sprites/sides/<scheme>/<p>/` (edit those too). Or change the painting code and
  `--bake-sprites --force <part>`. Doc: docs/DEVELOPING.md 7 "Sprites as PNGs".
- **Update or add 3D unit/weapon/mount/beast models (`Data/meshes/units3d.bin`):** all 204 modular parts are authored in Three.js under `tools/gltf/parts/*.mjs`
  (`bodies`, `limbs`, `heads`, `weapons`, `props`, `mounts`, `beasts`, shared primitives in `tools/gltf/geom.mjs`: `+Y` up, `+Z` forward,
  `material.userData.materialId` = `0..13` from `UnitMatTable`, linear AO in `COLOR_0`, outward CCW winding, ~8–10 radial segments to keep `Detail 0` light).
  Rebuild the full pack standalone with `cd tools/gltf && npm run build-all` (no Blender needed),
  copy to `bin/Release/net10.0/Data/meshes/units3d.bin` when running `--no-build`, then verify with `IRONFIELD_TROOPS` / `IRONFIELD_TROOP_VIEWS` and `--bench-3d 1500`.
- **Add a count of men or a per-man price in the campaign:** armies are `Balance.ArmyScale` (3) times the base numbers. Write a count
  as `Scaled(n)` and anything paid per man or derived from `Rules.Strength` as `Rules.PerMan(x)` (docs/DEVELOPING.md 5.7).
  With ArmyScale 1 the campaign must play exactly as before; compare `--selftest CampaignRun`'s pressure line at 1 and 3.
- **Add a realm:** an entry in `Data/factions.json` (`palette` = a new `Style.Sides` entry in both `Standard()` and `ColorBlind()`,
  with its own `Emblem` charge; `home`; four six-troop `lines` (`Troops.MaxTier`) of its culture, common or kin troops), a culture (root, `kin`,
  `flavour`), its `relations`, and place/lord names in `Data/names.json`. New maps need a new `WorldMap.CurrentLayout`
  (existing layouts must keep their realm homes). `SelfTest.SevenRealms` checks heraldry and lines.
- **Add a piece of captain gear:** an entry in `Data/gear.json` (slot weapon/shield/body/helm/horse; look = an existing sprite part;
  horse = a mount id from troops.json). `Gear.Validate` (run by `SelfTest.Armoury`) checks it.
- **Add a campaign balance value:** add the field with its default to `Balance` (CampaignState.cs) AND to `Data/campaign.json` (they must match; `SelfTest.BalanceMatchesData` fails otherwise).
- **Add a field to the save:** add a public field with a default on the class in `CampaignState.cs` (System.Text.Json, `IncludeFields`).
  Old saves still load (missing fields keep their default). There is no migration: bumping `CampaignState.CurrentVersion` makes
  older saves be refused (`SelfTest.RefuseOldSave`), so bump it only when old saves can no longer be read correctly.
- **Add a battle option from the campaign:** field on `BattleOptions`, set it in `Campaign.PrepareBattle`, read it in `Battle`.
- **Add a key action:** add to `Act` enum and `Controls.Defaults`; read with `ctl.Pressed(Act.X)`; list it in the F1 help (`Hud.Help`).
- **Add a campaign panel/button:** a method in the matching `MapScreen.*.cs` file using `Ui` (`ui.Button(...)` returns true on click); call the
  `Campaign` action and put a returned error string in the `note` field (drawn by `Note(r)`).
- **Add a shader parameter:** declare it in the effect's uniform list in `Shading.cs` (see `GlslEffect.Uniform`), use the name in
  the GLSL; set with `effect.Parameters["Name"].SetValue(...)`. GLSL rules: README "Shaders" section.
- **Add an event:** a storylet in the fitting `Data/events/<theme>.json`: `moments` (when the director may draw it), `when` (conditions,
  `Campaign.GlobalConds`), a `cast` (roles with `where` conditions, `Campaign.CastConds`), `weight`/`cooldown`/`once`/`heavy`, and choices
  with `cost`, `needs`, an `outcome`, or a `check` (`skill`/`man`/`trait`/`nature` against a number) with `pass`/`fail` (and `great`/`awful`);
  an outcome's `do` uses verbs from `Campaign.Verbs` and `then` queues a follow-up. Events the code raises are in `Campaign.CodeRaised`.
  A new condition or verb is an entry in its table plus its case. `--selftest EventsValidate` checks the files; `--events 4` shows the spread.
- **Add an origin:** an entry under `births` or `pasts` in `Data/origins.json` (effects: gold, renown, food, horses, opinion_realm, skill:Id:N, gear:id, wear:id, men:troop:N, free, buff:effect:days (a boon: an effect from effects.json tagged `origin`, 0 days = the whole campaign, never harmful); a `perk`; `age`; an `icon` from `Kit.IconNames`) and a story event with `"when": ["origin:<id>", "day>=14"]` in `Data/events/origins.json`. `SelfTest.CharacterCreator` validates it.
- **Add a camp event:** a storylet in `Data/events/camp.json` at the `camp` moment with a `man` cast (`where`: `nature:X`, `tie:Rivals`, `veteran`, `old`, `hurt`...;
  `other` is found from his ties), holes {man} {other} {company} {home}, verbs `man_deed` (with the outcome's `deed`), `man_hurt`, `man_leaves`, `tie` (needs `other`), `mention`.
- **Add a man's talk line:** an entry in `Data/talk.json` with topic `man_greet`/`man_men`/`man_home`/`man_tie`, optional `nature` and `when` (`Campaign.TalkWhens`); `SelfTest.CampTalk` validates it.
- **Add talk lines:** an entry in `Data/talk.json` `lines` (topic id from `Campaign.Topics` or `greet`; optional mood warm/even/cold/hostile, temper = a lord trait, outcome yes/no, `war`). The most fitting lines win; `ValidateTalk` (run by `SelfTest.TalkBondsWants`) refuses unknown keys and needs a greeting per mood and a yes line per topic. A new topic is an entry in `Campaign.Topics` plus cases in `TopicsFor`, `CannotAsk`, `Odds` (if checked) and `Grant`.
- **Add a sound:** add a `Cue` in `Audio.cs`, a case in `Synth.Make` (`AudioSynth.cs` / `AudioSynth.Combat.cs` / `AudioSynth.Creatures.cs` / `AudioSynth.World.cs`) built from its `Random` and a level in `Synth.Peak`; emit from the sim with `Sound(Cue.X, pos)`; listen with `--sounds /tmp/snd [filter]`.
- **Add a music score:** add a score entry in `Data/music/*.json` using `AudioBank` voices (`Data/audio/instruments.bank`); `MusicLibrary.Validate` (checked in `SelfTest.SoundsMade`) verifies voices, stems, timing, levels and loop seams; listen with `--sounds /tmp/snd <score_id>`.

## Invariants and gotchas (break these and things fail subtly)

- Headless code (Battle*, Squad, Units, Troops, Terrain, Campaign/*) must not use MonoGame graphics/audio/input.
- The 16 realm subcultures in `Data/factions.json` are the peoples of the drawn map's places (docs/archive/WORLDMAP.md WM5): a place's culture may be one
  (`Settlement.Culture`), and `Factions.PeopleOf` gives the realm culture it belongs to (never read a realm culture's `kin` as its people: the
  League's kin include the Azure). `bandit` is still `"waiting": true`: no realm fields it (`Factions.Validate` refuses a waiting culture a realm holds).
- Ground positions are `Vector2(X = world X, Y = world Z)`; height comes from `Terrain.Height(pos)`.
- Faction ids index `CampaignState.Factions`; realms founded in play (F5) carry `FactionState.Founded` (ids past the save's
  `DataRealms`; never test `id >= Factions.All.Count`, the data may have grown since the save). A map's realm layout comes from
  `CampaignState.Layout` (0 = the old fixed bands, kept for old saves; 1 = realms grow from `home` in `factions.json`;
  2 = also climates, ridges, four rivers on the 620 map; 4 = also routed roads, lakes and ponds, map bridges, field plots, woods in stands;
  5 = the drawn world, `Data/world.json`, the same for every seed: `WorldMap.CurrentLayout`, what new campaigns get; `Generate(seed)` with no layout
  makes `GeneratedLayout`, 4). A seed's map must never change for an existing layout: put new
  generation behind a new layout number. Party counts scale with `WorldMap.PartyScale` (land area past the 392 map). Use the instance
  `campaign.FactionNames[f]` (not a static list) and `Factions.Get(f)`, which sees founded realms once `Factions.Bind` ran (the `Campaign` constructor does it).
- The career rank is derived (`Campaign.Rank`), never stored; `CaptainState.BestRank` only remembers which beats were shown.
- Team 0 = player side, team 1 = enemy. Palette 3 = bandits (and, for now, monsters). `PartyKind.Caravan` parties (merchants,
  pilgrims) belong to a realm but are not soldiers: they never hunt, and `Party.Prey` (you robbed them) makes them hostile to you. `PartyKind.Monster` parties have no
  faction (`SideOf` = -3; `Campaign.Outlaw` covers brigands and monsters: no pay, no drill). Troops with culture `wild` are creatures:
  never recruited, outside the upgrade trees, not taken prisoner. `Squad.Alive` is refreshed every tick by `UpdateSquad`.
- `AttackDir` is named from the attacker's side; the defender must block `Dirs.Mirror(swing)`.
- MonoGame `Color * float` also scales alpha; use `Color.Lerp` for tints (`Mat` forces opaque).
- Render targets sample upside down on GL: `uv.y = 0.5 - 0.5*ndc.y`. Vertex shaders end with `FIXUP_POSITION`.
- No MSAA (breaks context creation on Mesa/Xvfb); FXAA in post. HiDef profile is required.
- Self-test battles: with an idle player the AI enemy wins in ~30 s at every level; that is expected (balance assumes the player fights).
- If you change sim behaviour, the `--selftest` printed numbers (battle times, arrow losses...) move; that is fine as long as it ends `selftest ok`.
- Code style: file-scoped namespace `Ironfield`, nullable on, terse expression-bodied members, `///` summary comments,
  British spelling in user-facing text ("colour", "armour"), UI text in short plain sentences (see docs/DESIGN.md "Voice").

## Keeping this map current

- After adding, removing, renaming or moving types or methods: run `tools/codemap.sh` and commit `docs/CODEMAP.md`
  (`tools/check.sh` fails if it is stale).
- Keep files focused: a class that grows past ~600 lines gets split into partial files by area (`Name.Area.cs` for screens,
  `NameArea.cs` for the sims), and a method past ~80 lines gets its natural steps pulled out into named methods.
- After changing architecture, data flow, commands, env vars or a recipe above: update this file in the same commit.
- Player-facing rules belong in `README.md`; campaign design in `docs/CAMPAIGN.md`. Keep this file about navigating the code.
